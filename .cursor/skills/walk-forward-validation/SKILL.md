# Walk-forward validation

Метод из [agiprolabs/claude-trading-skills](https://github.com/agiprolabs/claude-trading-skills) (MIT). Здесь нет vectorbt-контура: проверяем **правила на уже закрытых paper-сделках**, разрезая их по времени.

Случайный сплит и «подобрали порог на всех 81» — запрещены. Это подгонка.

## Как резать выборку

Сортировать сделки по `opened_at` / времени входа.

```
Окно 1: [==== train ====][ test ]
Окно 2:     [==== train ====][ test ]
```

- **Train** — на нём выбираем порог или «это правило имеет смысл».
- **Test** — только счёт. Порог не крутить.
- Между окнами щель **embargo** ≥ горизонта сделки (для пампа-шорта часто часы–сутки; для 333/em — пока открыт стоп). Не класть в train сделку, которая ещё не закрылась к старту test.

Мало данных (< 30 сделок в test) — не объявлять победу. Написать «мало» и показать обе стороны.

Для крипты лучше **rolling** (свежее окно), не копить весь 2025-й год в train.

## Прогон фильтра

Есть факт (сделка уже открыта). Предложение — «не входили бы, если бы правило X».

```
KEEP  = сделка проходит новое правило
DROP  = сделка отсекается
ΔPnL  = сумма PnL(KEEP) − сумма PnL(факт)
ликвидации в KEEP vs факт
плюсовые DROP — цена правила
```

Сначала train: если DROP режет в основном минусы и не трогает топ — кандидат. Потом те же пороги на следующем отрезке. Если на test ΔPnL отрицательный или топ семьи просел — **не внедрять**.

Сетка порогов (откат 10/11/12, since 60/90/180) крутить **только на train**. На test — один выбранный набор.

## Прогон выхода

Симуляции `scripts/simulate_*.py` — это другой выход на тех же входах. Тоже: подобрать ступени на раннем куске, проверить на позднем. Не хвалить сетку, которая выиграла один месяц.

## Признаки подгонки

- Порог прыгает от окна к окну (12% → 7% → 15%).
- Выигрыш сидит в 3 сделках.
- Работает на одной монете.
- Train красивый, test в минусе.
- После 20 переборов «нашлось» — это multiple testing; относиться как к слабому сигналу.

Грубо: если смотрели K вариантов правил, разовый плюс на test должен быть устойчивым по знаку хотя бы в двух окнах.

## Практика в этом репо

1. Закрытые сделки: API `/api/paper/trades?status=closed&variant=…` или JSON/скрипты `scripts/eval_entry_filters.py`, `analyze_paper_closed.py`.
2. Не читать будущее: поле на входе (`entry_json`, `metrics`, `since_peak_min`, `pump.trigger`) — да; то, чего в момент входа не было — нет.
3. Семьи отдельно: не валить t20 и 333 в один walk-forward.
4. В чат: N train/test, KEEP/DROP, PnL, ликвидации, вердикт.

Не подключать чужой `walk_forward.py` из Solana-репо — у нас свои сделки и поля.
