# Risk management

Метод из [agiprolabs/claude-trading-skills](https://github.com/agiprolabs/claude-trading-skills) (MIT), обрезан под эту лабораторию: Bybit USDT-перпы, бумажные счета $1000 на вариант, без Solana/PumpFun.

Иерархия: **выживание → сохранение → рост**. Правило, которое чуть поднимает PnL ценой крупных ликвидаций, — плохое правило.

## Счёт варианта

Каждый `t20` / `p10` / `mln` / `333` / `em6` / … — отдельный виртуальный депозит $1000. Не суммировать семьи в один «портфель», пока пользователь не просил. Маржа и ×10 уже в paper; ликвидации ≈ движение цены против нас ~9–10% при дефолтном MMR.

Считать по закрытым сделкам варианта:

| Метрика | Смотреть |
|---|---|
| PnL $ и % к $1000 | Итог |
| Win rate, profit factor | PF < 1 — стратегия не окупает минусы |
| Avg win / avg loss | Асимметрия |
| Max drawdown | Пик equity → дно |
| Ликвидации / стоп в пол | Аварийный хвост |
| Серия минусов | 5+ подряд — не крутить размер, крутить правило |

## Просадка (ответ, не «ещё фильтр»)

| DD от пика счёта | Действие агента |
|---|---|
| 0–10% | Разбор как обычно |
| 10–20% | Уменьшить предлагаемый риск; не расширять вход |
| 20–30% | Только диагностика: вход vs выход vs монета |
| >30% или несколько ликвидаций | Стоп предложений «ослабить шлюз» |

Восстановление: −20% требует +25%; −50% требует +100%.

## Что считать риском здесь

- **Одна монета / один пик** не должна решать судьбу счёта. Повторный вход в тот же `peak_ts` после стопа у копий уже запрещён.
- **Корреляция.** Несколько альтов в одном пампанувшем рынке — одна ставка. Не хвалить «диверсификацию», если 5 шортов открылись в один час.
- **Хвост.** Три ликвидации (в заметках: STRK, WUSDT, KAIA) важнее, чем средний винрейт. Но фильтр, который их режет и убивает плюсовой топ t20/p10, — отказ.

## Не предлагать

- Мартингейл, усреднение в минус, сдвиг стопа дальше.
- Живой размер позиции и ордера на биржу (ТЗ: система не торгует за человека).
- Общий стоп «все варианты» без команды — счета независимы специально.

## Быстрые формулы

```
risk_amount = account * risk_pct          # для будущего живого сайзинга; paper сейчас фикс
max_dd = max((peak - value) / peak)
need_to_recover = abs(dd) / (1 + dd)      # dd отрицательный, напр. -0.20 → +0.25
```

Если пользователь спрашивает «какой лот» — 1% риска на сделку как база, не больше 2%, half-Kelly если есть устойчивый WR и payoff. До этого не масштабировать.
